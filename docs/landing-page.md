# Transparency. 인터랙티브 랜딩

기존 Vite·JavaScript 앱에 `?view=landing` 경로를 추가했습니다. 제품 상세·구매·내 고민 등 기존 주소는 유지합니다. 홈의 **브랜드 경험** 버튼에서도 랜딩을 열 수 있습니다. 배경·문구·이미지·렌즈 설정은 `landing-config.js`에서 변경합니다.

monopo의 상호작용을 참고해 새 코드로 작성했습니다. 원본 사이트의 로고·폰트·셰이더·렌즈 이미지를 가져오지 않았습니다. 사진은 이 프로젝트에 있던 Transparency. 캠페인과 세럼 제형 이미지를 사용합니다.

## 설치·실행

Node.js 22 LTS와 npm을 권장합니다. 저장소를 처음 내려받는 경우:

```bash
git clone https://github.com/ziziisnzizi/Transparency..git transparency
cd transparency
npm ci
npm run dev
```

기본 개발 주소는 `http://localhost:5173/?view=landing`입니다. 기존 작업 폴더에서는 `npm ci`부터 실행하면 됩니다.

배포용 빌드와 로컬 확인:

```bash
npm run build
npm run preview
```

기본 미리보기 주소는 `http://localhost:4173/?view=landing`입니다. Vite가 다른 포트를 선택하면 터미널에 표시된 주소에 `?view=landing`을 붙입니다.

기존 기능의 단위 테스트:

```bash
node --test --test-concurrency=1
```

렌즈와 배경의 실제 WebGL 픽셀 검사는 선택 실행입니다. Playwright와 Chromium을
설치한 뒤 다음 명령을 사용합니다. 개발 서버는 필요하지 않습니다.

```bash
npm install --no-save playwright
npx playwright install chromium
npm run verify:landing
```

이미 설치된 Chromium을 쓸 때는 `PLAYWRIGHT_CHROMIUM_EXECUTABLE`에 실행 파일
경로를 지정합니다. 검사 결과와 소스 해시는 임시 폴더의
`transparency-landing-webgl.json`에 기록합니다. 출력 위치는 `LANDING_QA_OUTPUT`으로
바꿀 수 있습니다. 모든 검사용 요청은 메모리에서 처리합니다.

## 전체 코드 구성

| 파일 | 역할 |
| --- | --- |
| `landing-config.js` | 브랜드·내비게이션·영문/일문·사진 2개·팔레트·배경·렌즈 설정 |
| `landing-page.js` | 실제 제목·링크·버튼·작업 섹션·진행률 눈금 마크업 |
| `landing.css` | 풀스크린 레이아웃·계단형 제목·렌즈 테두리·정적 대체 화면·반응형 스타일 |
| `landing-background.js` | 풀스크린 WebGL 쿼드, GLSL 색 띠·노이즈 변형·이동하는 검은 영역·그레인 |
| `landing-lens-renderer.js` | 영문/일문 텍스처의 상보적 마스크·가장자리 굴절·RGB 분리 |
| `landing-text-lens.js` | 텍스트 래스터화·폰트/해상도·포인터 보간·렌즈 페이드·터치 언어 버튼 |
| `landing-runtime.js` | 배경 프레임·표시/숨김·동작 감소·네이티브 스크롤 진행률·정리 |
| `main.js`, `index.html` | 기존 라우팅에 랜딩을 연결하고 스타일 로드 |
| `scripts/verify-landing-webgl.cjs` | 독립된 Canvas2D 기준 픽셀과 실제 셰이더 결과 비교, 자원 정리 검사 |

## 문구·로고·이미지 변경

`landing-config.js`를 편집합니다.

- `brand.name`, `brand.text`: 페이지 제목과 보이는 브랜드 이름.
- `brand.logo`: 로고 이미지 경로. `null`이면 브랜드 텍스트를 표시합니다.
- `brand.logoInvert`: 검은 로고를 흰색으로 반전할지 여부. 이미 흰색인 로고나 원래 색을 유지할 이미지는 `false`로 설정합니다.
- `brand.href`, `navigation`: 실제로 이동할 주소와 작은 상단 메뉴.
- `title.en`, `title.ja`: 같은 영역에 놓을 영문·일문 3줄. 배열의 순서가 서로 대응합니다.
- `title.lineOffsets`: 각 줄의 왼쪽 시작점, 제목 영역 폭에 대한 백분율. 기본값은 `[0, 14, 25]`입니다.
- `intro`, `footer`: 하단 소개·스크롤 링크·푸터 문구.
- `works`: 이미지 섹션 두 개의 제목·설명·사진·대체 텍스트·이동 링크. 큰 사진을 바꿀 때 `imageWidth`, `imageHeight`도 실제 크기에 맞춥니다.

사진은 `public/images/`에 두고 `/images/파일명.webp`처럼 지정합니다. 제목은 각 언어를 3줄로 유지합니다. 긴 문구로 교체할 경우 데스크톱과 320px 화면에서 줄의 폭을 확인하세요.

## 배경 조절

모든 값은 `landing-config.js`의 `background`에 있습니다.

| 설정 | 의미 | 기본값 |
| --- | --- | --- |
| `palette.black` | 넓은 음영 영역 | `#03060b` |
| `palette.orange` | 번트 오렌지 띠 | `#c45124` |
| `palette.teal` | 옅은 청록 전환부 | `#a9cec9` |
| `palette.cobalt` | 코발트 띠 | `#264caa` |
| `palette.navy` | 남색 가장자리 | `#10152b` |
| `timeScale` | 포인터를 멈춰도 진행하는 자동 변화 속도 | `0.07` |
| `rotation` | 기본 띠 방향, 라디안 | `-0.55` |
| `distortion` | 저주파 노이즈에 따른 좌표 변형 | `0.65` |
| `grain` | 화면 좌표에 고정된 미세 입자 강도 | `0.035` |
| `maxPixelRatio` | 배경 렌더링 해상도 상한 | `1.5` |
| `pixelBudget` | 배경 픽셀 예산 | `1800000` |

색 띠는 두 단계 노이즈로 UV를 변형한 뒤, 회전하는 좌표계에서 오렌지→청록→코발트→남색으로 이어집니다. 별도의 넓은 검은 영역이 중앙과 가장자리를 오갑니다. 포인터 X는 변형 강도, Y는 노이즈 형태를 바꿉니다. 자동 시간 변화는 포인터 움직임과 독립적입니다. 정적 WebGL 대체 그라데이션에도 설정한 팔레트를 전달합니다.

배경은 최대 30fps로 그립니다. 히어로가 화면 밖으로 나가거나 문서가 숨겨지면 멈추며, 다시 보일 때 재개합니다. `prefers-reduced-motion: reduce`에서는 고정된 시간과 포인터로 한 장면만 그립니다.

## 텍스트 렌즈 조절

`landing-config.js`의 `lens`를 편집합니다.

| 설정 | 의미 | 기본값 |
| --- | --- | --- |
| `diameter` | 렌즈 지름, CSS px | `180` |
| `rimWidth` | 굴절이 발생하는 안쪽 가장자리 띠 폭 | `10` |
| `refraction` | 띠 안의 최대 방사형 변위, CSS px | `7` |
| `rgbOffset` | 띠 안의 RGB 샘플 간격, CSS px | `1.5` |
| `followRate` | 포인터 추적 속도. 클수록 빠르게 따라감 | `12` |
| `fadeRate` | 등장·언어 전환·사라짐 속도 | `10` |
| `maxPixelRatio` | 제목 텍스처 해상도 상한 | `2.5` |
| `pixelBudget` | 제목 레이어의 픽셀 예산 | `4000000` |

영문과 일문은 HTML 제목 안에 같은 위치의 두 레이어로 등록합니다. 데스크톱에서 폰트가 준비되면 각 줄의 실제 글꼴·자간·기준선을 사용해 별도의 텍스처 두 장을 만듭니다. 전체 HTML 화면을 캡처하지 않습니다. 제목은 최대 텍스처 크기와 픽셀 예산 안에서 높은 해상도로 그리며, 링크·버튼·사진은 일반 HTML입니다.

렌더링 규칙:

1. 원 바깥은 영문 텍스처입니다.
2. 원 안은 일문 텍스처입니다. 원 중심에서는 좌표 변위와 RGB 분리가 0입니다.
3. 안쪽 가장자리의 얇은 띠에만 방사형 변위와 RGB 오프셋을 적용합니다.
4. 실제 포인터가 영문 제목 줄 영역 밖으로 나가면 일문 표시가 사라지고 영문으로 돌아옵니다.
5. 히어로 밖으로 나가면 렌즈도 페이드아웃합니다.

위치와 페이드는 `1 - exp(-rate * deltaTime)`으로 보간해 프레임 속도가 달라도 비슷한 추적감을 유지합니다. 동작 감소 설정에서는 위치를 즉시 따라갑니다.

## 모바일·실패 대응·네이티브 동작

- 터치 환경에서는 렌즈를 생략하고 언어 버튼으로 HTML 제목을 전환합니다.
- WebGL 초기화·셰이더·텍스처 업로드 실패 또는 컨텍스트 손실 시 해당 렌더러를 정적 배경 또는 HTML 제목으로 대체합니다. 제목 대체 모드에서는 언어 버튼도 사용할 수 있습니다.
- 캔버스는 `pointer-events: none`, `aria-hidden="true"`이며 링크 클릭·키보드 포커스·스크롤을 가로채지 않습니다.
- 휠·터치 스크롤을 취소하거나 별도의 스크롤 라이브러리를 사용하지 않습니다. 스크롤 링크는 실제 앵커입니다.
- 작업 이미지 섹션은 두 개입니다. 데스크톱 눈금의 삼각형 마커는 브라우저의 실제 스크롤 위치를 따라갑니다.
- 라우트 이동과 HMR에서 프레임·이벤트·옵저버·텍스처·프로그램을 정리합니다. 기존 서비스의 장식 배경은 랜딩에 들어갈 때 해제하고 나올 때 다시 만듭니다.
- 녹화의 브라우저 UI·웹캠·쿠키 배너는 랜딩에 포함하지 않았습니다.

## 확인 항목

실행 후 다음 세 동작을 확인할 수 있습니다.

1. 포인터를 멈추고 기다려도 색 띠와 검은 영역이 움직입니다. 동작 감소 설정에서는 멈춥니다.
2. 원이 제목을 가로지를 때 원 밖의 영문은 유지되고 원 안만 일문으로 바뀝니다. 중심 글자는 선명하고 얇은 가장자리에서만 굴절과 색 분리가 보입니다.
3. 터치 또는 WebGL 미지원 환경에서도 HTML 제목·언어 버튼·상단 링크를 사용할 수 있습니다.

이 문서는 재현을 위한 실행·설정 안내이며, 실제 기기별 FPS나 모든 해상도의 성능을 보장하는 벤치마크는 아닙니다.

### 구현 후 확인한 결과

- Chromium 실제 WebGL에서 독립적인 원본 픽셀 기준으로 20개 검사를 통과했습니다.
  원 밖 영문·중심 일문·영문 복원은 최대 RGBA 오차 0이었고, 굴절·RGB 변화는
  설정한 가장자리와 안티앨리어싱 허용 범위 안에만 있었습니다.
- 포인터를 고정한 실제 랜딩에서도 배경 시간·그리기 횟수와 픽셀이 계속 바뀌었습니다.
  동작 감소 설정으로 바꾸면 정적 시간 3.4에서 추가 그리기를 멈췄습니다.
- 데스크톱 1440px와 터치 에뮬레이션 390px·320px에서 제목·내비게이션·언어 버튼을
  확인했습니다. WebGL을 사용할 수 없게 한 경우에도 HTML 제목·언어 전환·링크가
  유지되었습니다.
- 원 안팎 언어 전환·제목 밖 공개 해제·히어로 밖 페이드·네이티브 휠/앵커·키보드
  포커스·눈금 진행률·페이지 이동 후 GPU 자원 정리를 확인했습니다.
- 기존 단위 테스트 107개와 프로덕션 빌드를 통과했습니다.

셰이더 픽셀 검사는 Chromium ANGLE/SwiftShader에서 실행했으며, 실제 휴대전화의
발열·배터리·프레임률을 측정한 결과는 아닙니다.
